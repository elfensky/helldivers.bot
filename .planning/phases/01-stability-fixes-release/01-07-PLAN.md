<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `next/font/google` build step -> shipped assets | The font is fetched at build time and self-hosted from the app's own origin; no request leaves the visitor's browser for a third-party font host |
| Visitor browser -> font asset | Font files are served to every visitor from the app origin under the existing CSP |
| Build environment -> Google Fonts | The build machine makes an outbound request to fetch the face |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Information Disclosure | Third-party font hosting | low | mitigate | `next/font/google` downloads and self-hosts the face at build time, so no visitor request reaches a Google origin and no visitor IP is disclosed to a third party — this is the property that makes the chosen loader preferable to a stylesheet link |
| T-07-02 | Denial of Service | Build-time font fetch | medium | transfer | A Google Fonts outage fails the build rather than degrading production. The risk is transferred to the build pipeline, where a failed build is visible and blocks a bad release; the currently-deployed image is unaffected |
| T-07-03 | Tampering | Font asset integrity | low | accept | The face is fetched once at build time over TLS and baked into the image; at ASVS L1 the build-time supply chain for a font asset is accepted on the same terms as any other build-time dependency fetch |
| T-07-04 | Denial of Service | Layout overflow from changed metrics | medium | mitigate | Task 3's explicit narrow-width measurement at 300px and 260px, plus the visual-regression compare pass, catch a metric-driven layout break before release rather than after |
</threat_model>
