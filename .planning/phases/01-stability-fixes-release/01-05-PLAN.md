    Build the app image from local source and run it against a reachable database, then drive `/opengraph-image` and observe.

    Bound the effort explicitly: this task is time-boxed to a single focused attempt.     The sequence:
    1. Build the app image from local source using the CI compose file's build path, targeting the same platform the production image runs on.
    2. Boot it with a working `POSTGRES_URL` and the minimum required env (`UPDATE_KEY`, `UPDATE_INTERVAL`), with `WORKER_ENABLED` off so the poller does not muddy the logs.
    3. Request `/opengraph-image` and record the status, headers and body size. Under the 01-03 changes, a fallback is now identifiable by its `no-store` header and the absence of an `ImageResponse` construction.
    4. Drive the three edge-case map states from 01-04 through the *real* pipeline. Those tests mock `next/og`, so they prove the route's control flow, not that Satori and sharp accept the resulting tree. Seed or point the container at data producing each shape, or request the route with the season selected accordingly.

Check the first two by inspecting the running container before driving traffic — they are cheap and would explain the "only in the image" symptom directly.

    Write `.planning/phases/01-stability-fixes-release/01-OG-SHARP-REPRO.md` recording: the image tag and build command, the runtime env, each request made and what came back, each hypothesis and whether it was confirmed or ruled out, and a **Verdict** line reading exactly one of `REPRODUCED`, `NOT REPRODUCED` or `BLOCKED`, followed by one sentence of justification.

    Do not modify `src/` in this task.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-04 | Denial of Service | Investigation stalling the release | medium | mitigate | The explicit three-way stop condition and the `Verdict:` requirement bound the effort; a `NOT REPRODUCED` outcome is a defined completion, so plan 01-08 is never blocked on this |

<flagged_assumptions>
## Flagged Assumptions (edge probe — spec-less fallback)

- **Reproduction is not guaranteed.** This plan can complete without finding the cause, by design (D-10). That is recorded as an accepted outcome rather than a gap, and the STAB-02 success criteria are met by plans 01-03 and 01-04 independently of this plan's verdict.
- **The "only fires in the image" premise is inherited, not re-derived.** D-10 states the standalone Docker image is the only environment where the rejection has been observed. This plan takes that as given. If the rejection turns out to reproduce outside Docker during the run, that is a more useful finding than the plan expects and should be recorded prominently.
- **Platform parity is approximate.** The staging target is arm64 (Raspberry Pi Swarm) while a local build is most likely amd64. A `NOT REPRODUCED` verdict on one architecture does not clear the other; the document should name which platform it built for so a later reader knows what was actually tested.
</flagged_assumptions>
