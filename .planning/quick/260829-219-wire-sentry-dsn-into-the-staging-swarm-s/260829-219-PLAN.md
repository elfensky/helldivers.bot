<objective>
Wire GlitchTip error reporting into the staging Swarm stack by passing `SENTRY_DSN_FILE` from a new external Swarm secret, and update the docs that currently say Sentry is deliberately unset.

Purpose: staging currently reports nothing. `sentry.server.config.js` reads `process.env.SENTRY_DSN`, and `src/app/api/glitchtip/route.js` returns 503 when it is unset — which silently drops browser events too, because the client tunnels through that route. One env var fixes both directions.

Output: a ~10-line change across three files, in two atomic commits on `chore/staging-sentry-dsn`.

**Deployment ordering hazard — state this in the SUMMARY.** `docker stack deploy` refuses the whole stack if an `external: true` secret does not exist (`secret not found: helldiversbot_sentry_dsn`). Arcane Git Sync applies this compose on every commit to `develop`, so if this branch merges before the secret exists, the next staging deploy fails outright — not degraded, failed. The user must create the secret on a manager **before** the merge.
</objective>
